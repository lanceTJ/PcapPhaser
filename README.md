# FlowPhaser: Phase-aware Traffic Analysis with PcapPerturbator, PSS, FlowManifest, and PGCL

[![License: MIT](https://img.shields.io/badge/License-MIT-yellow.svg)](LICENSE)
[![Python 3.12+](https://img.shields.io/badge/python-3.12+-blue.svg)](https://www.python.org/)

## Overview

**FlowPhaser** is an open-source research framework for **phase-aware and robustness-aware traffic analysis**, released to support **reproducible research and open science**.

The framework consists of four tightly coupled but independently reusable components:

1. **PcapPerturbator**
   A PCAP perturbation framework for **controlled robustness evaluation**, supporting both lightweight streaming perturbations and TrafficManipulator-assisted **length-only** / **rate-only** perturbation generation.

2. **PSS (Potential Start-point based Segmentation)**
   A high-performance pipeline for **traffic phase segmentation** and **phase-level dataset generation** from raw PCAP files.

3. **FlowManifest**
   A reviewer-friendly, reproducible, leakage-free **parent-flow manifest and data splitting pipeline** ensuring all variants of the same parent flow stay together across splits.

4. **PGCL (Phase-guided Contrastive Learning)**
   A downstream learning framework that consumes **phase-level CSV datasets** generated by PSS and performs contrastive pretraining and supervised classification.

Together, these components support a composable experimental workflow from raw traffic, to perturbation and phase-aware preprocessing, to downstream learning evaluation.

## Component Summary

### PcapPerturbator

**PcapPerturbator** is a perturbation framework for generating controlled traffic variations before downstream analysis.

Key capabilities:

* Streaming packet-level perturbations such as loss, retransmission, reorder, and sequence offset
* TrafficManipulator-assisted **length-only** and **rate-only** perturbation stages
* File-level verification and metadata export for perturbation-strength tracking
* Batch-oriented PCAP processing for robustness experiments

PcapPerturbator can be used independently, or as a preprocessing / robustness-evaluation component before running PSS, FlowManifest, and PGCL.

See `PcapPerturbator/README.md` for detailed usage instructions.

---

### PSS: Potential Start-point based Segmentation

**PSS** implements a dynamic-programming-based traffic phase segmentation algorithm based on **Potential Starting Point Scoring**.

Key capabilities:

* PCAP → packet-level features → phase segmentation
* Phase-aware PCAP reconstruction
* Standard flow feature generation (via CICFlowMeter)
* Export of **phase-level CSV datasets** for ML

See `PSS/README.md` for detailed usage instructions.

---

### FlowManifest: Parent-Flow Manifest-Based Split Pipeline

**FlowManifest** is a reviewer-friendly, reproducible, leakage-free data splitting pipeline at the parent-flow level.

Key capabilities:

* Stable parent-flow ID generation ensuring origin and perturbed variants share the same ID
* Unified manifest management for all data views
* Parent-flow level train/val/test splits to prevent data leakage
* Label-balanced few-shot support set generation
* PA-FT (Perturbation-Aware Fine-Tuning) balanced sampling
* Built-in leakage checking and validation

FlowManifest consumes CSV datasets from PSS and provides manifest-based data loaders for PGCL.

See `FlowManifest/README.md` for detailed usage instructions.

---

### PGCL: Phase-guided Contrastive Learning

**PGCL** is a downstream learning framework designed to evaluate the effectiveness of phase-aware traffic representations.

Key capabilities:

* Self-supervised **phase-guided contrastive pretraining**
* Supervised fine-tuning for traffic classification
* Fully CSV-based (no PCAP dependency)
* Deterministic, configuration-driven training

PGCL consumes **CSV datasets via FlowManifest**.

See `PGCL/README.md` for detailed usage instructions.

## Typical Reproduction Workflow

A typical artifact evaluation workflow is:

1. **Run PcapPerturbator** on raw PCAP files
   → generate perturbed or robustness-test PCAP datasets

2. **Run PSS** on raw or perturbed PCAP files
   → generate phase-level CSV datasets

3. **Run FlowManifest** on the phase-level datasets
   → create parent-flow manifest and train/val/test splits
   → generate few-shot support sets
   → verify no data leakage

4. **Run PGCL** on the manifest-split datasets
   → reproduce downstream classification results

Each step is independently configurable and reproducible.

## Artifact Scope and Limitations

### Provided

* Implementations of the four FlowPhaser components and their documented data contracts
* Deterministic execution given identical inputs and configurations
* Configuration files aligned with those used in the paper
* Modular design for partial reuse, perturbation studies, and ablation studies

### Not Provided

* Original proprietary or restricted PCAP datasets used in the paper
* Pretrained downstream model checkpoints
* Large-scale experiments requiring extensive computational resources
* External third-party repositories required by sub-components unless explicitly vendored
* Project-specific orchestration callbacks between PcapPerturbator, PSS, and FlowManifest

Users may supply their own PCAP data or public datasets to evaluate the framework.
